# Runbook: резервні копії бази даних

_Власник: Андрій. Остання перевірка відновлення: 2026-09-30._

## Що і коли

PostgreSQL працює на тій самій VM, що й сервіс (поза docker compose). Щоночі cron на VM
запускає `/opt/poshtomat/backup.sh`:

1. переводить базу в режим лише читання — з 02:00 до 02:30 за Києвом база тримає
   блокування на запис: будь-який `INSERT`/`UPDATE` у цей час чекає або падає з помилкою;
2. знімає дамп і разом з ним копіює файли журналу подій, щоб вони були узгоджені;
3. знімає блокування, стискає дамп і відправляє його в об'єктне сховище;
4. видаляє копії, старші за 14 днів.

Читання (видача посилок за кодом теж починається з читання) у цей час працюють.

Після бекапу о 03:15 cron запускає нічну задачу сервісу: `docker compose run --rm worker
npm run expire`.

## Як перевірити, що бекап пройшов

```bash
ssh poshtomat-prod-1
sudo tail -n 20 /var/log/poshtomat/backup.log   # останній рядок: "backup ok <розмір>"
```

Якщо рядка за сьогодні немає — алерт `BackupMissing` уже мав прийти в #poshtomat-oncall.

## Відновлення

1. Зупинити сервіс: `docker compose -f deploy/compose.yaml stop api worker`.
2. Завантажити потрібну копію зі сховища: `/opt/poshtomat/fetch-backup.sh 2026-09-30`.
3. `sudo -u postgres pg_restore --clean -d poshtomat /tmp/poshtomat-2026-09-30.dump`.
4. Запустити сервіс і перевірити `GET /health` та кілька посилок в адмінці.

Відновлення на копії з учора займає ~10 хвилин.
